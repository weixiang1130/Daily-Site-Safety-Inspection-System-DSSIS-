# 工地檢視器

讓工地電腦看到戰情儀表板的**正規做法**。最大原則（2026-09-02 定案）：

> **工地一台普通電腦、沒有任何公司資料庫權限、只有網路，也要看得到儀表板。**

因此這個包**完全自足**：不連公司資料庫、不用申請任何權限、不用找 IT
開防火牆、不經雲端看板。解壓即用。

```
                    工地電腦（普通電腦＋網路，僅此而已）
                    ┌───────────────────────────────┐
雲端填報站 ─────────►│ safetyops-viewer/              │
氣象站平台 ─────────►│  內附 Python＋套件（免安裝）     │
人臉裝置(公網IP) ───►│  自帶 SQLite（免資料庫權限）     │
工地攝影機 ─────────►│  自帶收集程式（自己抓資料）      │
                    │  列控表工項（打包時烤入）        │
                    │        ↓                       │
                    │  瀏覽器 http://127.0.0.1:8000   │
                    └───────────────────────────────┘
```

## 這個包怎麼成立的

工地需要的每一樣資料**恰好都在外網**：表單／缺失（雲端填報站）、
環境數據（氣象站廠商平台）、在場人數（人臉裝置，公網 IP）、監視畫面
（攝影機就在工地）。唯一在公司內網的是 FinOps 計價進度——**工地版不顯示
它**，改以列控表工期推算的「預定進度」呈現（見下）。

關鍵取捨：

- **免安裝**：內附 Python embeddable 與全部 wheel。不碰系統、不寫登錄檔、
  不需要管理員權限，資料夾放桌面或 D 槽都行。
- **單一程序**：`site_runner.py` 一個程序＝儀表板伺服器＋三支收集程式
  （執行緒）。工地沒有人會維護工作排程，點一個檔全亮、關一個視窗全滅。
- **本機 SQLite**：不用 SQL Server、不用唯讀帳號。伺服器只聽 127.0.0.1，
  不對外服務。
- **列控表工項打包時烤入**（`bake_viewer_db.py`）：列控表只在公司拿得到，
  不烤的話那格永遠空白。缺失／環境／人數刻意**不烤**——活資料烤進去
  只會讓工地第一眼看到打包當天的舊數字，空白比過時誠實。

## 預定進度 ≠ 實際進度

工地版的進度是**依列控表工期推算的預定值**（每個葉工項算已過工期，
工期加權加總）。它回答「照計畫今天該做到哪」，**沒有實際值可對照、
看不出超前落後**，且為工期加權、非產值加權，與全程營運的 S 曲線有出入。
前端以中性樣式顯示「預定 X%」並寫明推算依據，絕不與公司牆上的
「實際 vs 預估」（FinOps）混用。實際值只在中央主機的內網版看得到。

## 打包與交付（在開發機上）

```bash
python backend/tools/make_site_package.py
```

產出 `dist/safetyops-viewer.zip`（約 35 MB）。打包時自動：

1. 從本機資料庫**烤入**工地主檔與列控表工項
2. 從本機 `.env.onprem` **代填**工地要用的設定（雲端同步權杖、氣象站
   帳密、人臉裝置與監視器位址、品牌名稱）——工地拿到就能用。
   FinOps／門禁帳密與 SECRET_KEY **不會**進包。

⚠ **包等同於憑證**（含雲端同步權杖與氣象站帳密），交付走隨身碟或
內部管道，不可放公開網路。外流時換掉對應權杖／密碼即可。

## 工地端操作（讀我.txt 也有寫）

1. 解壓到任何位置，點「**啟動儀表板.cmd**」——瀏覽器自動開啟
2. 開機自動啟動：執行一次「安裝開機自動啟動.cmd」（非管理員可跑，
   之後在背景執行、沒有黑窗）
3. 首次啟動後：缺失約一分鐘內出現（首輪全量同步）、環境與人數十五分鐘內到齊

## 列控表改版時（約每月一次）

工項是烤進包裡的，改版時不用重發 35 MB 的包，寄一個小檔即可：

```bash
# 在公司的機器上
python backend/tools/import_schedule.py "<新列控表.xlsx>" --site BD04   # 另一棟 BD05
python backend/tools/export_internal.py          # 產出約 150 KB 的 .internal.json
```

把 `.internal.json` 寄到工地，放進檢視器資料夾，點「**更新工項.cmd**」。

## 限制

- **沒有計價進度**（實際 vs 預估）——那需要公司內網，工地版以預定進度替代
- 資料新鮮度：環境 15 分、人數 5 分、表單同步 12 小時（與中央主機相同，
  因為跑的是同一套收集程式）
- 多個工地各發一包時，每包都會各自輪詢雲端與氣象站——目前的頻率下
  額度綽綽有餘，工地數量到兩位數時再回頭調 `SYNC_INTERVAL`
