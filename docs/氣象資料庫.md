# 氣象資料庫

微型氣象站的 5 分鐘歷史，存在中央主機的 SQL Server（與出工資料庫副本同一個
資料庫），用來累積「天氣 × 出工／工種」的分析資料。

## 與戰情室即時資料的分工

| | 戰情室即時（`device_readings`） | 分析歷史（`weather_readings`） |
|---|---|---|
| 程式 | `collectors/weather.py` | `collectors/weather_archive.py` |
| 排程 | SafetyOps-Weather 每 15 分鐘 | SafetyOps-WeatherArchive 每日 10:00 |
| 抓什麼 | 今天最新一筆 | 已過完的日子，整天 5 分鐘序列 |
| 關機期間 | 沒有、不補 | 下次執行自動補齊 |
| 格式 | 一列一個指標（長格式） | 一列一個時間點，指標並排 |

兩者互不影響。牆面不需要即時環境數據時才考慮停用 SafetyOps-Weather。

## 資料流

```
氣象站廠商平台（保留一年以上的 5 分鐘歷史）
   ↓ 每日 10:00 SafetyOps-WeatherArchive（關機錯過則開機登入後補跑）
   ↓ collectors/weather_archive.py：從上次歸檔日往前重疊 3 天，抓到昨天
SQL Server weather_readings（5 分鐘）
   ├→ v_weather_daily（每測站每日彙總）
   └→ v_worklog_weather_daily（主場站天氣 × 每日出工）
```

- 只歸檔 `WEATHER_SITE_MAP` 列出的測站；第一次從 `WEATHER_ARCHIVE_FROM`（預設
  2024-01-01）開始回補，一次查 7 天。
- 每次重抓最近 3 天：斷線測站恢復後補傳的資料也會進來。重抓是整段刪除再寫入，不會重複。
- 資料與進度（`weather_archive_progress`）同一個交易，寫一半失敗就下次從同一天重來。
- 測站斷線、平台沒資料的日子也視為歸檔過，不會每天重查。
- 不花 Netlify 額度：直接連廠商平台，不經雲端。

## 資料表

**`weather_readings`**：一列＝一台測站的一個 5 分鐘時間點

| 欄位 | 內容 |
|---|---|
| `site_code` | 工地代碼（`WEATHER_SITE_MAP`） |
| `device_id` | 測站 mac |
| `reading_at` | 台北時間 |
| `pm25`、`pm10` | μg/m³ |
| `noise` | dB，即時音壓級（非 8 小時日時量平均） |
| `temperature`、`humidity` | °C、% |
| `heat_index` | 熱指數；廠商未提供時由溫濕度推算 |
| `hazard_level` | 0～4，依 `app/hazard.py` 自行判定（廠商的危害等級不可信） |

不是每台測站都有溫濕度；沒有的欄位為 NULL。

**`v_weather_daily`**：每測站每日一列。工作時段取 07:00–17:00。

| 欄位 | 內容 |
|---|---|
| `samples` | 當天有資料的 5 分鐘格數（滿格 288），偏低代表測站斷線 |
| `temp_min／avg／max`、`humidity_avg` | 全天 |
| `heat_index_max` | 全天最高 |
| `heat_index_max_work`、`heat_index_avg_work` | 工作時段 |
| `hours_hi_lv2_work`、`hours_hi_lv3_work` | 工作時段熱指數 ≥ 32.2／≥ 40.6 °C 的時數（高氣溫作業熱危害預防指引附表二第二、三級） |
| `pm25_avg／max`、`pm10_avg／max` | 全天 |
| `noise_avg_work`、`noise_max` | 工作時段平均、全天最高 |
| `hazard_level_max` | 全天最高危害等級 |

**`v_worklog_weather_daily`**：主場站（`PRIMARY_SITE_CODE`）天氣 × 每日出工，
一天一列，從出工資料的第一天開始。以天氣日期為底，**沒有出工回報的日子也在**
（`reports`＝0），停工日才看得到。`weekday_mon1`：1＝週一 … 7＝週日。

## 分析查詢範例

熱危害時數與出工人數：
```sql
SELECT report_date, weekday_mon1, headcount, heat_index_max_work, hours_hi_lv2_work
FROM v_worklog_weather_daily
ORDER BY report_date;
```

各工種在不同熱危害程度下的平均人數（工種要先在出工資料庫頁歸類）：
```sql
SELECT COALESCE(a.trade_group, t.trade) AS trade,
       CASE WHEN w.hours_hi_lv2_work >= 4 THEN '熱' ELSE '一般' END AS 熱度,
       COUNT(DISTINCT r.report_date) AS 天數,
       SUM(t.headcount) * 1.0 / COUNT(DISTINCT r.report_date) AS 平均人數
FROM worklog_trades t
JOIN worklog_reports r ON r.id = t.report_id
LEFT JOIN worklog_trade_aliases a ON a.trade = t.trade
JOIN v_worklog_weather_daily w ON w.report_date = r.report_date
GROUP BY COALESCE(a.trade_group, t.trade),
         CASE WHEN w.hours_hi_lv2_work >= 4 THEN '熱' ELSE '一般' END
ORDER BY trade, 熱度;
```

## 注意

- **沒有雨量**：測站沒有雨量計。降雨停工只能從「該日無出工回報」間接看，或另接
  中央氣象署資料。
- 同一工地的不同棟別共用主場站的天氣。
- 檢視表由歸檔程式每次執行時建立或更新（`CREATE OR ALTER VIEW`），只支援 SQL Server。
