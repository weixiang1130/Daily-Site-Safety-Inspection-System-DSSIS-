# 地端戰情室

## 為什麼要搬

戰情室原本和填報系統一起放在雲端，但它是**大螢幕整天開著、每分鐘更新**的東西：
監視畫面、環境數據、人數，每一次更新都是一次雲端函式呼叫。填報一天幾十次，
戰情室一天幾萬次——額度幾乎都花在牆上那一面，而不是真正的業務。

更關鍵的是，戰情室要的資料**來源本來就都在公司網路內**：

| 資料 | 來源 | 雲端取得的困難 |
|------|------|----------------|
| 監視畫面 | 工地 NVR | 主機限制來源 IP，雲端第一次請求就被回 403，而雲端沒有固定對外 IP 可加白名單 |
| 進出場人次 | 公司門禁資料庫 | 內部資料庫不對外開放 |
| 環境數據 | 廠商氣象站平台 | 可從外部取得，但沒有理由繞一圈 |

為了讓雲端看得到監視畫面，原本得在公司內網另外跑一支推送程式，把畫面傳到
雲端儲存區再讓瀏覽器讀回來——同一張圖片在網路上來回兩趟。搬到地端之後，
這一整條路（推送程式、儲存區、權杖驗證）都不需要了。

## 搬完之後的樣子

```
工地手機 ──填報──> 雲端（Netlify）
                      │
                      │ sync_forms 定時拉取（只拉統計要用的欄位）
                      ▼
     公司內網  ┌─── 地端伺服器（FastAPI + SQL Server）───┐
               │                                        │
   NVR ────────┤  collectors/    app/                    │
   門禁資料庫 ─┤   weather        /api/dashboard         │──> 戰情室大螢幕
   氣象站平台 ─┤   access         /api/cctv/snapshot     │
               │   sync_forms                            │
               └────────────────────────────────────────┘
```

**填報留在雲端**——工地是拿手機在現場填，必須從外網進得來。
**戰情室在地端**——資料來源都在內網，而且不再吃雲端額度。

雲端就算暫時連不上，牆上仍看得到最後一次同步的內容。

## 安裝

### 1. 設定檔

複製 `.env.onprem.example` 成 `.env.onprem`，填入實際值。

> `.env.onprem` 含資料庫、監視器與氣象站的帳號密碼，已被 `.gitignore` 排除，
> **不可進版控**。本 repo 為公開。

### 2. 套件

```bash
cd backend/onprem
pip install -r requirements.txt
pip install -r requirements-mssql.txt   # 用 SQL Server 時
pip install pyodbc                      # 讀門禁資料庫用
```

### 3. 啟動 API

```bash
python -m uvicorn app.main:app --host 0.0.0.0 --port 8000
```

大螢幕開 `http://<地端主機>:8000/static/dashboard.html`。

`PUBLIC_DASHBOARD=true` 可讓大螢幕免登入（放在公司內網才適用）。
**這台機器不要對外網開放**，否則等於把全公司的缺失資料公開。

### 4. 啟動收集程式

各自獨立，任何一支停掉不影響其他來源：

```bash
cd backend/onprem
python -m collectors.weather --loop       # 環境數據，預設 15 分鐘一輪
python -m collectors.access --loop        # 進出場人次，預設 5 分鐘一輪
python -m collectors.sync_forms --loop    # 從雲端拉表單，預設 5 分鐘一輪
```

用「工作排程器」設成開機自動啟動。三支都是遇到單次失敗會記錄並繼續，
不會整個停掉——工地不會有人盯著它們。

首次同步請先跑一次 `python -m collectors.sync_forms --full`，把既有資料全部拉回來。

## 各部分的狀況

| 項目 | 狀態 |
|------|------|
| 儀表板 API（環境／人數／熱危害／最新表單） | 完成，已驗證 |
| 監視器地端直連 | 完成，實測可取像（雲端會被回 403） |
| 氣象站收集 | 完成，實測可登入取值 |
| 雲端 → 地端表單同步 | 程式完成並驗證；雲端的匯出端點**尚未部署** |
| 門禁人數收集 | 程式完成，**尚未實地驗證**（見下） |

### 門禁人數尚未驗證

撰寫當下開發用的筆電連不到資料庫網段的 1433 埠：主機 ping 得到、DNS 也解析得到，
但 TCP 不通，應是網段之間的防火牆規則。因此**檢視表的欄位結構還沒實地看過**。

`collectors/access.py` 因此不寫死欄位名稱，而是連上之後看實際有哪些欄位再對應；
對應不到就不寫入任何資料並印出實際欄位。寧可牆上顯示「尚無資料」，也不要掛一個
猜出來的數字上去——疏散時有人會照著那個數字點名。

在地端主機上先跑一次確認結構（會遮蔽姓名與證號）：

```bash
python tools/inspect_access_view.py
```

若自動對應挑錯了，用 `ACCESS_COL_*` 指定正確欄位，見 `.env.onprem.example`。

## 個資

門禁資料含姓名與員工編號，屬第三人個資。`collectors/access.py`
**只寫入彙總後的人數**，不把任何個人欄位存進本系統的資料庫，也不寫進記錄檔。
