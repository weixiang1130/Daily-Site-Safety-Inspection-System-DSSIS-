# 專案結構

## 一句話說明

**填報留在雲端**（工地拿手機在現場填，要從外網進得來）、
**戰情室跑在地端**（中央主機整天開著，內網資料源只有它拿得到）、
**工地看儀表板用完全自足的免安裝檢視器**——自帶 SQLite 與收集程式，
只需要網路，不碰公司任何資料庫（見 `工地檢視器.md`）。
三邊共用同一份前端與同一套表單定義。

```
工地手機 ──填報──> Netlify（雲端）◄─┐
                      │            │ sync_forms 各自定時拉取
                      ▼            │
        公司內網   中央地端主機     工地檢視器（免安裝包，只要網路）
   （NVR／FinOps／NAS 列控表）      （氣象站／人臉裝置也直接抓）
             │                         │
             ▼                         ▼
        戰情室大螢幕              工地辦公室螢幕
```

## 目錄總覽（三層）

```
frontend/   前端——三邊共用同一份
backend/    後端——雲端函式、地端服務、收集程式、工具、腳本、資料
docs/       文件
```

根目錄其餘的是部署設定與把關機制，位置由平台或工具決定，不可搬：
`netlify.toml`、`package.json`（Netlify 要求在根目錄）、
`netlify/database/migrations/`（Netlify 規定的固定路徑）、
`.githooks/`（pre-commit 去識別化把關）、`.env*`（環境設定，不進版控）。

## 前端 `frontend/`

**雲端、地端、工地檢視器共用同一份**。頁面用相對路徑呼叫 API，
差異由 `/api/branding` 的旗標與網址參數決定。

| 檔案 | 用途 |
|---|---|
| `index.html` | 登入頁 |
| `home.html` | 今日作業首頁、缺失概況 |
| `fill.html` | 自主檢查表填報 |
| `coord.html` | 每日協議、巡視及處理紀錄表 |
| `findings.html` | 缺失清單與複驗 |
| `admin.html` | 工地／廠商／密碼管理 |
| `dashboard.html` | **工地看板**（五區塊）。帶 `?k=` 或雲端開啟時自動轉往 dashboard-detail |
| `dashboard-detail.html` | **戰情室大螢幕**（原 dashboard.html）。帶 `?k=<權杖>` 時進入雲端看板模式（備援） |
| `board-settings.html` | 看板管理：聯絡人、作業循環時段、公告、無災害起算（雲端為準、防互蓋） |
| `site-board.js`、`board-core.js`、`site-board.css` | 工地看板的邏輯、時鐘引擎與樣式 |
| `common.js` | 共用工具：品牌、API 呼叫、狀態標籤 |
| `brand.css`、`style.css` | 設計 token 與版面 |

深色主題只掛在 `dashboard-detail.html`（`class="war theme-dark"`）——牆上隔幾公尺看
與坐在桌前填表是不同的觀看條件，因此刻意拉高對比；填報頁維持淺色。

## 後端 `backend/`

### `cloud/`（Netlify Functions，TypeScript）

只負責**收表單**。

| 檔案 | 用途 |
|---|---|
| `functions/api.mts` | 所有 `/api/*` 路由（含工地看板設定的維護端點） |
| `lib/auth.ts`、`lib/pdf.ts`、`lib/font-coverage.ts` | 登入／PDF／字型涵蓋 |
| `lib/site-board.ts` | 看板設定的驗證（與地端 `app/site_board.py` 維持同一契約） |
| `assets/fonts/` | PDF 內嵌中文字型 |

**不可刪除的路由**：`/api/v1/export`（地端同步的生命線）、
`/api/v1/ingest/device` 與 `/api/v1/device/latest`（已公開的廠商 API，
見 `docs/API_SPEC.md`）、`/api/v1/ingest/wallboard` 與 `/api/wallboard`
（雲端看板備援）。

### `onprem/`（FastAPI，Python）——中央地端主機與工地檢視器共用

**`app/` —— API 與商業邏輯**

| 檔案 | 用途 |
|---|---|
| `main.py` | 所有路由。FinOps 沒資料的工地自動退到「預定進度」（列控表工期推算） |
| `db.py` | 資料模型與連線。預設 SQL Server；工地檢視器設 `DB_BACKEND=sqlite` 用本機檔 |
| `auth.py`、`pdf.py`、`envfile.py`、`seed.py` | 登入／PDF／設定檔（也認得「連線設定.env」）／初始資料 |
| `hazard.py` | 環境量測值的危害分級（**法規門檻，不可自行四捨五入**） |
| `site_board.py` | 看板設定的驗證（與雲端 `lib/site-board.ts` 維持同一契約） |
| `heat_guidance.py`、`noise_guidance.py` | 熱危害與噪音各級應辦措施 |
| `cctv.py` | 監視器直連取像 |
| `work_hazards.py` | 工項名稱 → 應注意危害的關鍵字對應 |

**`collectors/` —— 資料收集程式**（中央主機經工作排程執行；工地檢視器由 `site_runner.py` 以執行緒帶著跑 weather／face／sync_forms／worklog／osha_news 五支）

| 檔案 | 抓什麼 | 從哪裡 |
|---|---|---|
| `weather.py` | 環境數據 | 廠商氣象站平台 |
| `face.py` | 進出場人次（彙總計數） | 人臉辨識裝置 |
| `access.py` | 進出場人次 | 公司門禁資料庫（1433 未放行，備援） |
| `sync_forms.py` | 表單、缺失、工地、廠商 | 雲端 `/api/v1/export` |
| `finops.py` | 工程進度（財務） | 公司 FinOps 資料庫 |
| `push_wallboard.py` | 整份儀表板快照 → 雲端 | 本機 API（`WALL_ENABLED` 才動，備援） |
| `worklog.py` | 本日出工回報 | 工務所 LINE 群組（經 webhook 落地的 Google 試算表） |
| `osha_news.py` | 職安新知 | 職安署網站新聞稿 |

**`tools/` —— 開發與維運工具**

| 檔案 | 用途 |
|---|---|
| `deidentify.py` | **推送前的把關**。掃描真實人名／廠商／工地／內部字詞 |
| `bake_viewer_db.py` | 打包時把工地主檔與列控表工項烤進檢視器的 SQLite |
| `make_site_package.py` | **產生工地檢視器安裝包**（見 `docs/工地檢視器.md`） |
| `build_frontend.py` | 雲端建置：`frontend/` → `dist/` |
| `build_pdf_font.py` | 字型 OTF→TTF 並精簡。**執行期不可子集化** |
| `import_schedule.py` | 匯入列控表供「今日重點工項」使用 |
| `export_internal.py`、`import_internal.py` | 列控表改版時把工項以小檔送到工地檢視器（刻意不含 FinOps 進度） |
| `inspect_access_view.py` | 探測門禁檢視表結構（遮蔽姓名與證號） |
| `import_sites.py`、`import_paper_records.py`、`extract_forms.py` | 資料匯入 |
| `create_db.py`、`inspect_db.py`、`gen_migrations.py`、`purge_demo_data.py` | 資料庫維護 |
| `e2e_test.py` | 端對端測試 |

**`scripts/` —— 排程進入點**（工作排程器呼叫的 .cmd 與安裝腳本）

`setup_onprem_host.ps1` 一鍵安裝中央主機（環境檢查、套件、排程、防火牆）；
`run_*.cmd` 是各排程的進入點；`run_hidden.vbs` 讓排程不彈黑窗。

**`data/`** —— 表單定義（`forms.json`）與本機主檔（`*.local.*`，不進版控）。
