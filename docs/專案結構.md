# 專案結構

## 一句話說明

**填報留在雲端**（工地拿手機在現場填，要從外網進得來）、
**戰情室跑在地端**（大螢幕整天開著，資料來源都在公司網路內）。
兩邊共用同一份前端與同一套表單定義。

```
工地手機 ──填報──> Netlify（雲端）
                      │
                      │ sync_forms 定時拉取
                      ▼
        公司內網   地端伺服器 ──> 戰情室大螢幕
                      ▲
        NVR／門禁DB／氣象站平台
```

---

## 前端 `frontend/`

**雲端與地端共用同一份**。頁面用相對路徑呼叫 API，所以同樣的檔案兩邊都跑得動；
差異由 `/api/branding` 回傳的旗標決定（例如 `war_room` 決定首頁要不要顯示戰情室入口）。

| 檔案 | 用途 | 部署到雲端 |
|---|---|---|
| `index.html` | 登入頁 | ✅ |
| `home.html` | 今日作業首頁、缺失概況 | ✅ |
| `fill.html` | 自主檢查表填報 | ✅ |
| `coord.html` | 每日協議、巡視及處理紀錄表 | ✅ |
| `findings.html` | 缺失清單與複驗 | ✅ |
| `admin.html` | 工地／廠商／密碼管理 | ✅ |
| `dashboard.html` | **戰情室大螢幕** | ❌ 僅地端 |
| `common.js` | 共用工具：品牌、API 呼叫、狀態標籤 | ✅ |
| `brand.css` | 設計 token（顏色、字級、間距） | ✅ |
| `style.css` | 元件與版面 | ✅ |
| `assets/`、`fonts/` | 裝飾圖與字型說明 | ✅ |

`dashboard.html` 的排除設定在 `tools/build_frontend.py` 的 `CLOUD_EXCLUDE`。
**檔案本身不刪**——地端服務讀的是同一個 `frontend/` 目錄。

深色主題只掛在 `dashboard.html`（`class="war theme-dark"`）。牆上大螢幕隔三五公尺看，
和坐在桌前填表單是不同的觀看條件，因此刻意拉高對比；填報頁維持淺色。

## 後端

### 雲端 `backend/cloud/`（Netlify Functions，TypeScript）

只負責**收表單**。戰情室相關的程式碼已全數移除（2026-08-25）。

| 檔案 | 用途 |
|---|---|
| `functions/api.mts` | 所有 `/api/*` 路由 |
| `lib/auth.ts` | 登入、session、密碼雜湊 |
| `lib/pdf.ts` | 產生檢查表與協議紀錄 PDF |
| `lib/font-coverage.ts` | 檢查字型涵蓋哪些字，未涵蓋者換成 □ |
| `assets/fonts/` | 內嵌 PDF 的中文字型（實際使用 `.ttf`；`.otf` 是轉檔來源） |

**不可刪除的路由**：

- `/api/v1/export` —— 地端靠它同步表單資料。刪掉牆上就沒有東西。
- `/api/v1/ingest/device`、`/api/v1/device/latest` —— 已公開的廠商推送 API
  （見 `docs/API_SPEC.md`）。沒人呼叫就不產生費用。

### 地端 `backend/onprem/`（FastAPI，Python）

戰情室與地端資料庫。

**`app/` —— API 與商業邏輯**

| 檔案 | 用途 |
|---|---|
| `main.py` | 所有路由。**開頭必須先 `load_env()`**，否則設定讀不到 |
| `db.py` | 資料模型與連線。預設 SQL Server，可切 SQLite |
| `auth.py` | 登入 |
| `pdf.py` | PDF 產生 |
| `envfile.py` | 讀取 `.env.onprem` |
| `hazard.py` | 環境量測值的危害分級（**法規門檻，不可自行四捨五入**） |
| `heat_guidance.py` | 熱危害各級應辦措施（指引附表三） |
| `noise_guidance.py` | 噪音各級應辦措施（設施規則 §300、§300-1） |
| `cctv.py` | 監視器直連取像 |
| `work_hazards.py` | 工項名稱 → 應注意危害的關鍵字對應 |
| `seed.py` | 初始資料 |

**`collectors/` —— 資料收集程式**

各自獨立執行，任何一支停掉不影響其他來源。

| 檔案 | 抓什麼 | 從哪裡 |
|---|---|---|
| `weather.py` | 環境數據（PM、噪音、溫濕度、熱指數） | 廠商氣象站平台 |
| `access.py` | 進出場人次 | 公司門禁資料庫（唯讀檢視表） |
| `sync_forms.py` | 表單、缺失、工地、廠商 | 雲端 `/api/v1/export` |
| `config.py` | 共用設定讀取（實作在 `app/envfile.py`） | — |

## 資料庫遷移 `netlify/database/migrations/`

**這個路徑是 Netlify 平台規定的，不可搬到 `backend/` 底下。**
只作用於雲端；地端沒有遷移工具，改用 `db.py` 的 `_add_missing_columns()`
從模型自動補欄位。

## 工具 `tools/`

| 檔案 | 用途 |
|---|---|
| `deidentify.py` | **推送前的把關**。掃描真實人名／廠商／工地／內部字詞 |
| `build_frontend.py` | 雲端建置：`frontend/` → `dist/`，排除戰情室頁面 |
| `build_pdf_font.py` | 字型 OTF→TTF 並精簡。**執行期不可子集化** |
| `inspect_access_view.py` | 探測門禁檢視表結構（遮蔽姓名與證號） |
| `import_schedule.py` | 匯入列控表（MS Project 匯出）供「今日重點工項」使用 |
| `import_sites.py`、`import_paper_records.py`、`extract_forms.py` | 資料匯入 |
| `create_db.py`、`inspect_db.py`、`gen_migrations.py` | 資料庫維護 |
| `purge_demo_data.py` | 清除示範資料 |
| `e2e_test.py` | 端對端測試 |
| `push_snapshots.py` | **已失效**：把監視畫面推到雲端用，雲端接收端點已移除 |
